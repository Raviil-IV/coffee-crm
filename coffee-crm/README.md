# Coffee CRM — мини-CRM для кофейни

Веб-приложение для учёта заказов в кофейне: REST API для работы с клиентами, напитками и заказами. Данные хранятся в PostgreSQL. Приложение упаковано в Docker и готово к развёртыванию на сервере.

## Технологический стек

- **Backend:** Node.js + Express
- **База данных:** PostgreSQL 16
- **ORM:** Prisma
- **Контейнеризация:** Docker + Docker Compose
- **Документация API:** Swagger/OpenAPI (доступна на `/docs`)

## Структура проекта

```
coffee-crm/
├── docker-compose.yml
├── Dockerfile
├── package.json
├── prisma/
│   ├── schema.prisma        # модель данных (аналог init.sql)
│   └── seed.js              # тестовые данные
└── app/
    ├── index.js             # точка входа, Swagger, обработка ошибок
    ├── database.js          # подключение к БД (PrismaClient)
    ├── schemas.js           # валидация входных данных
    ├── util.js              # вспомогательные функции
    └── routes/
        ├── customers.js
        ├── drinks.js
        ├── orders.js
        └── analytics.js
```

> **Примечание:** вместо файла `init.sql` из ТЗ таблицы создаёт Prisma (`prisma db push` при старте контейнера), а тестовые данные загружает `prisma db seed`.

## Быстрый старт (Docker)

```bash
docker compose up -d --build
```

При первом запуске автоматически создаются таблицы и загружаются тестовые данные:
**7 клиентов, 9 напитков, 17 заказов**. Повторный запуск данные не дублирует.

После старта:

- **Веб-интерфейс (панель управления):** http://localhost:3000
- **Swagger-документация:** http://localhost:3000/docs
- **PostgreSQL:** `localhost:5432` (пользователь `coffee`, пароль `coffee`, БД `coffee_crm`)

Остановить: `docker compose down` · Полный сброс данных (вместе с volume): `docker compose down -v`

## Веб-интерфейс

На главной странице `/` доступна панель управления на три вкладки:

- **Клиенты** — добавление и удаление клиентов;
- **Напитки** — добавление, изменение и удаление напитков (редактирование — по кнопке «Изменить»);
- **Заказы** — создание заказа (клиент + несколько позиций с количеством, живой подсчёт суммы), смена статуса (pending/ready/completed), удаление.

Аналитика осталась доступна через API (`/analytics/*`, см. Swagger `/docs`).

Интерфейс — статические файлы в `app/public/` (vanilla JS, без сборки), обращается к тем же REST-эндпоинтам, что и curl-примеры ниже. Мобильная вёрстка поддержана.

## Локальный запуск без Docker

```bash
cp .env.example .env   # указать DATABASE_URL
npm install
npx prisma db push     # создать таблицы
npx prisma db seed     # загрузить тестовые данные (опционально)
npm start              # сервер на http://localhost:3000
```

## Эндпоинты

### Клиенты (`/customers`)

| Метод  | Путь              | Описание                          |
|--------|-------------------|-----------------------------------|
| GET    | `/customers`      | Список всех клиентов              |
| GET    | `/customers/{id}` | Клиент по ID                      |
| POST   | `/customers`      | Создать клиента (`name`, `phone?`)|
| DELETE | `/customers/{id}` | Удалить клиента (каскадно с заказами) |

### Напитки (`/drinks`)

| Метод  | Путь            | Описание                                |
|--------|-----------------|-----------------------------------------|
| GET    | `/drinks`       | Меню всех напитков                      |
| GET    | `/drinks/{id}`  | Напиток по ID                           |
| POST   | `/drinks`       | Добавить напиток (`name`, `price`, `category`) |
| PUT    | `/drinks/{id}`  | Обновить напиток (частичное обновление) |
| DELETE | `/drinks/{id}`  | Удалить напиток (409, если есть в заказах) |

### Заказы (`/orders`)

| Метод  | Путь                 | Описание                                            |
|--------|----------------------|-----------------------------------------------------|
| GET    | `/orders`            | Список всех заказов (с суммой)                      |
| GET    | `/orders/{id}`       | Заказ по ID: клиент, напитки, количество, общая сумма |
| POST   | `/orders`            | Создать заказ (`customer_id`, `items: [{drink_id, quantity}]`) |
| PUT    | `/orders/{id}/status`| Изменить статус (`pending` / `ready` / `completed`) |
| DELETE | `/orders/{id}`       | Удалить заказ                                       |

### Аналитика (`/analytics`)

| Метод | Путь                                 | Описание                              |
|-------|--------------------------------------|---------------------------------------|
| GET   | `/analytics/top-drinks`              | Топ-5 самых заказываемых напитков     |
| GET   | `/analytics/customer-stats/{id}`     | Статистика клиента: заказы и сумма    |
| GET   | `/analytics/revenue`                 | Общая выручка (`?status=completed` — фильтр по статусу) |

## Примеры curl-запросов

```bash
# Список клиентов
curl http://localhost:3000/customers

# Создать клиента
curl -X POST http://localhost:3000/customers \
  -H 'Content-Type: application/json' \
  -d '{"name":"Тест Тестов","phone":"+79990001122"}'

# Создать заказ (2 эспрессо + 1 латте для клиента 1)
curl -X POST http://localhost:3000/orders \
  -H 'Content-Type: application/json' \
  -d '{"customer_id":1,"items":[{"drink_id":1,"quantity":2},{"drink_id":4,"quantity":1}]}'

# Заказ по ID с расчётом суммы
curl http://localhost:3000/orders/1

# Сменить статус заказа
curl -X PUT http://localhost:3000/orders/1/status \
  -H 'Content-Type: application/json' \
  -d '{"status":"completed"}'

# Аналитика
curl http://localhost:3000/analytics/top-drinks
curl http://localhost:3000/analytics/customer-stats/1
curl http://localhost:3000/analytics/revenue
```

## Обработка ошибок

Приложение возвращает понятные HTTP-коды с JSON-описанием ошибки:

| Код  | Случай                                            |
|------|---------------------------------------------------|
| 400  | Ошибка валидации (обязательные поля, `price <= 0`, `quantity <= 0`, неверный статус) |
| 404  | Ресурс не найден (клиент, напиток, заказ)         |
| 409  | Напиток используется в заказах и не может быть удалён |
| 500  | Внутренняя ошибка сервера                         |

Формат ответа об ошибке: `{ "error": "описание" }`.

## Валидация данных

- Обязательные поля: `name` клиента, `name`/`price`/`category` напитка, `customer_id` и непустой `items` у заказа;
- `price > 0`, `quantity > 0` (целые числа);
- При создании заказа проверяется существование `customer_id` и всех `drink_id`;
- Статусы заказа: `pending` (в обработке), `ready` (готов), `completed` (выдан).

## Правила работы с данными

- **Удаление клиента** — его заказы удаляются каскадно (`ON DELETE CASCADE`).
- **Удаление напитка** — если напиток есть в заказах, удаление запрещено (HTTP 409), старые заказы сохраняются.
- **Сумма заказа** не хранится в БД — вычисляется на лету как сумма `price * quantity` по позициям.
- Создание заказа и его позиций выполняется в одной транзакции.
- Все операции с БД асинхронные (async/await).

## Устранение неполадок

- **Порт 3000 занят** — поменяйте маппинг портов в `docker-compose.yml` и `PORT` в окружении.
- **Хотите пересоздать БД с нуля** — `docker compose down -v && docker compose up -d --build` (тестовые данные загрузятся заново).
- **Для продакшена** замените пароль `coffee` в `docker-compose.yml` на надёжный и не публикуйте порт PostgreSQL наружу.
