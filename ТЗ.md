# Техническое задание: Мини-CRM для кофейни

## 1. Общее описание
Разработать простое веб-приложение для учета заказов в кофейне. Приложение должно предоставлять REST API для работы с клиентами, напитками и заказами. Данные хранятся в PostgreSQL. Приложение должно быть упаковано в Docker-контейнер для развертывания на сервере.

---

## 2. Технологический стек
- **Backend:** Python + FastAPI (или Node.js + Express, на твой выбор)
- **База данных:** PostgreSQL 16
- **ORM:** SQLAlchemy (для Python) или Prisma (для Node.js)
- **Контейнеризация:** Docker + Docker Compose
- **Документация API:** Swagger/OpenAPI (автоматически генерируется в FastAPI)

---

## 3. Структура базы данных

### Таблица 1: `customers` (Покупатели)
```sql
CREATE TABLE customers (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    phone VARCHAR(20),
    registered_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Таблица 2: `drinks` (Меню напитков)
```sql
CREATE TABLE drinks (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    price DECIMAL(10, 2) NOT NULL,
    category VARCHAR(50) NOT NULL
);
```

### Таблица 3: `orders` (Заказы)
```sql
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    customer_id INTEGER REFERENCES customers(id) ON DELETE CASCADE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    status VARCHAR(20) DEFAULT 'pending'
);
```

### Таблица 4: `order_items` (Позиции заказа)
```sql
CREATE TABLE order_items (
    id SERIAL PRIMARY KEY,
    order_id INTEGER REFERENCES orders(id) ON DELETE CASCADE,
    drink_id INTEGER REFERENCES drinks(id),
    quantity INTEGER NOT NULL DEFAULT 1
);
```

## 4. Требования к API

### 4.1. Клиенты (`/customers`)
- `GET /customers` — получить список всех клиентов
- `GET /customers/{id}` — получить клиента по ID
- `POST /customers` — создать нового клиента
- `DELETE /customers/{id}` — удалить клиента

### 4.2. Напитки (`/drinks`)
- `GET /drinks` — получить меню всех напитков
- `GET /drinks/{id}` — получить напиток по ID
- `POST /drinks` — добавить новый напиток в меню
- `PUT /drinks/{id}` — обновить информацию о напитке
- `DELETE /drinks/{id}` — удалить напиток из меню

### 4.3. Заказы (`/orders`)
- `GET /orders` — получить список всех заказов
- `GET /orders/{id}` — получить заказ по ID с полной информацией (клиент, напитки, количество, общая сумма)
- `POST /orders` — создать новый заказ (принимает customer_id и список drink_id с количеством)
- `PUT /orders/{id}/status` — изменить статус заказа (pending/ready/completed)
- `DELETE /orders/{id}` — удалить заказ

### 4.4. Аналитика (`/analytics`)
- `GET /analytics/top-drinks` — топ-5 самых заказываемых напитков
- `GET /analytics/customer-stats/{customer_id}` — статистика клиента (количество заказов, общая сумма потрачено)
- `GET /analytics/revenue` — общая выручка за все время

## 6. Требования к Docker

### 6.1. `docker-compose.yml`
Должен содержать два сервиса:
1. **postgres** — PostgreSQL 16
   - Переменные окружения: POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB
   - Порт: 5432
   - Volume для сохранения данных

2. **app** — приложение
   - Зависит от postgres
   - Порт: 8000 (или 3000 для Node.js)
   - Переменные окружения для подключения к БД
   - Автоматический запуск миграций/создания таблиц при старте
   - Автоматическое заполнение тестовыми данными при первом запуске

## 7. Дополнительные требования

1. **README.md** должен содержать:
   - Описание проекта
   - Инструкцию по запуску (`docker-compose up -d`)
   - Ссылку на Swagger-документацию (обычно `/docs` для FastAPI)
   - Примеры curl-запросов для тестирования API

2. **Обработка ошибок:**
   - Возвращать понятные HTTP-коды (404, 400, 500)
   - JSON-ответы с описанием ошибки

3. **Валидация данных:**
   - Проверять обязательные поля
   - Проверять, что price > 0
   - Проверять, что quantity > 0
   - Проверять существование customer_id и drink_id при создании заказа

4. **Расчет общей суммы заказа:**
   - При получении заказа по ID (`GET /orders/{id}`) возвращать вычисленную общую сумму (сумма price * quantity для всех позиций)

## 8. Критерии приемки

Приложение считается готовым, если:
- ✅ `docker-compose up -d` поднимает БД и приложение без ошибок
- ✅ Swagger-документация доступна и работает
- ✅ Все эндпоинты из раздела 4 возвращают корректные данные
- ✅ Тестовые данные автоматически загружаются при первом запуске
- ✅ Можно создать заказ, добавить в него несколько напитков, получить полную информацию о заказе с расчетом суммы

---

## 9. Примечания для разработчика (ИИ)

- Используй асинхронный код (async/await) для работы с БД
- Все операции с БД должны быть в транзакциях
- При создании заказа автоматически вычислять общую сумму не нужно — это делается на лету при чтении
- Статусы заказов: `pending` (в обработке), `ready` (готов), `completed` (выдан)
- При удалении клиента удаляются все его заказы (ON DELETE CASCADE)
- При удалении напитка из меню старые заказы с этим напитком должны сохраняться
